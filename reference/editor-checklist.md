# The Editor Stage

This is the piece the old ChatGPT system never had, and the single biggest reason the new cards will beat the old ones. After a card is drafted, run it through this checklist **as an adversary** — your job is to *break* the card, not to approve it. Default to "rewrite" when unsure.

Run every drafted card through all 27 checks. Output one of: **PASS**, **REWRITE** (with the fix applied), or **DROP** (with a one-line reason). Checks 18–20 are the **Cold-Solve Gate** (card-rules #16–18) — the anti-ambiguity core: a knower must be able to produce the exact answer from the visible side alone, cold, first time. When in doubt, run the cold-solve test — cover the answer and ask "could I have written exactly this?"

Checks 25–26 are the **retrieval-load pair** (card-rules #23–24), and they ask a different question from all the rest: not *is each blank answerable* but *is the whole card passable*. A grouped reveal is graded all-or-nothing, so a card can pass every other check on this list — every blank fair, every row cold-solvable — and still be unpassable because it demands ten answers at once. Run 25 on every card that hides more than four things.

| # | Check | How to test it | If it fails |
|---|-------|----------------|-------------|
| 1 | **One answer** | Hide the cloze. Read the stem. Could someone who knows this material write a *different* correct answer? | Rewrite the stem to constrain to one answer, or DROP. |
| 2 | **No tautology / leak** | Is the answer stated or strongly implied by the visible words? | Rewrite so the stem cues without revealing. |
| 3 | **Grounded** | Is every claim supported by the highlight's `context` paragraph? Any invented detail? | Remove/fix the unsupported part. If the fact needs info that isn't there, DROP and flag. |
| 4 | **Fully clozed** | Are there other distinct testable facts left untested in the VISIBLE text — a goal, purpose, function, cause, or key qualifier riding along as scenery? Run this on EVERY card, definitions included. | Cloze it (add a `c`-number) or add a sibling card. |
| 5 | **List handled** | Is this a list where only some items are clozed and the rest revealed? | Restructure into sibling cards or one grouped-reveal card (card-rules Layer B #4). |
| 6 | **Crisp cloze** | Is the hidden span a tight keyword/number, or a long fuzzy phrase you couldn't recall verbatim? For a two-way definition, is the **c2 meaning side ~3-6 words** (crisp), or a bloated 8+ word sentence no one reproduces verbatim (R12)? | Tighten the deletion to the key term; crisp up a bloated c2 and move the fuller wording to Back Extra. `check_cards.py` warns on any single blank hiding ≥9 words. |
| 7 | **Cohesive, not crammed** | Are the items a genuine single set, or unrelated facts forced together? A real cohesive list stays ONE card at any length (Parker's preference). Also: does the prose exceed ~60 words? | Split ONLY if the items are unrelated or the prose is too long; keep real lists whole. |
| 8 | **Worth it** | Is the card built around genuinely testable knowledge, or around soft connective filler? | Re-anchor the card to the real fact. Do NOT drop a yellow-highlighted item — if it's truly uncardable even after checking card-rules Rule 0, flag `needs_human_check`. (Non-yellow highlights are Parker's own notes and never enter the pipeline at all.) |
| 9 | **Hint clean** | Could the hint replace the answer and mean the same thing? | Make it a slot-label, or remove it. |
| 10 | **Standalone** | Any deixis, source-artifact word, or sentence-initial pronoun? Does it read cold, right after an unrelated card? | Rewrite to be self-contained. |
| 11 | **Back Extra earns its place** | Does it add a real edge (Distinguish/Pitfall/Why…), or just restate the Text? | Rewrite it, don't pad. |
| 12 | **Application-fit** | Only when the source's profile asks for it (e.g. `profiles/emt.md`): for a sign / finding / threshold / "which one" fact, is there a paired scenario card forcing a real decision, or is this pure recall? | Draft the paired application cloze (one stem, one decision). Skip this check entirely for profiles that don't call for scenarios. |
| 13 | **Coin-flip hinted** | Is the cloze a direction/binary (increase/decrease, indicated/contraindicated, open/closed) with nothing in the stem forcing the choice? | Add a forced-choice `::option/option` hint. An unhinted coin-flip blank is unanswerable — REWRITE. |
| 14 | **Prereq-closed** | Does the card rely on an undefined term that makes it understandable only in source/lecture context (Parker's "wonky cards")? | Fold in a one-clause definition or spawn a sibling definition card — only from grounded context, else flag `needs_human_check`. |
| 15 | **Cue, not crutch (isolation test)** | Picture this card ALONE in Parker's ONE shuffled megadeck (MCAT + EMT + genetics + languages, all interleaved). Does the visible side give enough SITUATIONAL context to answer it — WITHOUT a parenthetical/appositive/descriptor that states the answer's own definition? Could a non-knower decode the answer from the cue? | Strip the definitional leak (move it to Back Extra). If now too vague, add SITUATIONAL (not definitional) context. Target: knower-can / non-knower-can't. |
| 16 | **No cross-card give-away** | For a scenario/classify card, are its correct answers spelled out — as an `Ex:` line, a definition, or the same wording — on a SIBLING card in this same batch? (A knower and non-knower both then win by pattern-matching the neighbor, not by reasoning.) | Re-write the scenario with a FRESH exemplar not used verbatim elsewhere, or DROP it if a sibling already tests the same discrimination. |
| 17 | **List complete vs the real source** | For any card that states a count ("N factors/signs/steps") or enumerates a list: does it test EVERY item the *full source page* lists — not just the ones that fit the extractor's context window? Lists that spill across a page break are the trap. If the highlight is a `list_lead_in`, read the whole list off the page before trusting the count. | Add the missing item(s); correct the stated count. A stated count that ≠ the number of clozed items is the tell (`check_cards.py` flags an undercount). |
| 18 | **Cold-solve (open-set)** | Cover the answer. Could a student who KNOWS the material produce THIS exact answer from the visible stem alone, on first sight? Or is the blank one of a wide-open universe of plausible true fills ("list 3 things her religion opposes", "you must [some action]") with nothing visible singling out the intended one? | REWRITE per card-rules #16: add the situational anchor that forces exactly one answer (name the entity/scenario), flip to the constrained direction, or cloze only the load-bearing verb+object. A genuinely closed taxonomy is fine — only *open* answer-spaces fail. |
| 19 | **All-blanks-at-once husk** | Cover everything hidden under EACH single cloze number. Is the visible remainder mostly connective scaffolding ("the ___ of ___ applies to ___"), because two mutually-dependent spans are both hidden under the same number? | REWRITE per card-rules #17: re-number the spans (c1, c2…) so each card reveals one as the anchor and tests the other (two-way), or re-scope so one substantial fact is hidden per number. |
| 21 | **List reads as a list** | Is the Text a list of items to produce (lead-in + rows that are basically clozes)? Are the rows separated by `<br><br>`, so the NUMBER of answers owed is visible at a glance — or packed with single `<br>` into one block? | Re-lay it out with `<br><br>` between rows (card-rules #19). Prose that merely uses `<br>` between sentences is NOT a list — leave it. |
| 20 | **Hint is a form-label, not a first-letter leak** | Does any `::hint` equal the first letter(s) of its own answer while the stem contains NO spelled acronym those letters build? (Licensed only for a real mnemonic: SAMPLE, DCAP-BTLS.) Does any hint restate the answer's meaning? | REWRITE per card-rules #18: remove the letter hint (prefer exposing shared structure and clozing the crisp discriminator), or replace with a count/form hint. `check_cards.py` warns on a first-letter-matching hint with no acronym in the stem. |

| 22 | **Row label cues, never restates** | On any `LABEL → {{answer}}` row: read the label aloud, then the answer. Is the answer a paraphrase of the label ("Arrival at hospital → notify dispatch of arrival")? Or does the label say nothing at all ("Miscellaneous → …")? | REWRITE per card-rules #20: test what the label does NOT already say, or drop the row. A row that answers itself is padding, not coverage. |
| 23 | **Absolute statements are anchored** | Is the stem a *never / always / only / must not* rule with ONE unhinted blank at the end? Cover it: could several true things fit ("sadness", "skin color", "being tired")? | REWRITE per card-rules #21: add a slot-label `::hint`, add a visible contrast naming the rejected alternative, or flip to the positive fact with the negation as a sibling cloze. |
| 24 | **The cloze is the unit of knowledge** | Is the thing worth knowing *that the item exists* (one of N questions to ask, N functions to name) — while the items sit VISIBLE and only a filler word inside each is hidden? Ask: does answering this card train what he'll actually be asked to produce? | REWRITE per card-rules #22: cloze the items themselves, or change the archetype (test the organizing structure, keep the list in Back Extra, add an application vignette). Never cloze filler because the real answer is inconvenient. |
| 25 | **Retrieval load — is the card PASSABLE?** | Count the answers under one cloze number that carry no per-item cue. ≤4 → fine. 5–7 → is there a real handle (a spelled mnemonic the card teaches, a structure that regenerates the members)? ≥8 → there is no legitimate shape. Ask the honest question: could Parker produce ALL of them, in one breath, and be graded on all of them at once? | CHUNK per card-rules #23: semantic partition into named sub-groups of ≤4 as separate notes + an anchor note; or convert the rows to cued/keyed ones; or change the archetype. Give every resulting note a `Roster:` line carrying the full set with its own members bolded. |
| 27 | **A value column is one note per key** | Are the answers under one cloze number a *column of numbers* keyed by a label (ages, months, severities)? Cover them and ask the harder question: could he derive a hidden value from its visible neighbours — do the numbers trend with the key? | SPLIT per card-rules #25: one note per key, each asking a single value, with the source table attached as an image on the back (`image_side: "back"`). Never restate the other keys' values in Back Extra prose — that recreates the leak in the one place he looks after answering. |
| 26 | **The split didn't leak** | Having chunked, check the shape of the fix: is any enumerated list fanned across DIFFERENT cloze numbers on ONE note? Blank each number in turn — do the other members sit there visible? | REWRITE per card-rules #24: move each sub-group to its own NOTE. Sibling numbers on one note make N cards that each reveal N−1 answers — recall by elimination, which is the defect the chunking was supposed to cure. |

**Run checks 18–24 on EVERY ROW, not just on the card as a whole.** A multi-row card can read as answerable while individual rows are self-answering or wide open — that is exactly how the 2026-07-30 failures survived a 20-point pass. A card is only as good as its worst row.

**Safety overlay:** if the card states a number, dose, threshold, or time window, or the extractor marked its grounding `PARTIAL`/`NOT_FOUND`, set `needs_human_check: true` regardless of the verdict above. These go to Parker for a human glance before he promotes them from `claude review` into `Book Highlights`.

**Tone:** be strict. A smaller deck of cards that are all genuinely good beats a big deck where one in five is vague. When you genuinely can't decide between two phrasings, keep the one that reads most like a human tutor quizzing him.
