## Shape decision — SPLIT per condition, not one grouped panel

The parent's default was a §12b decision panel (3 rows, one c1). Drafted it, then killed it on
a per-row cold-solve (rules 16–22 run per ROW): **row 3's condition key contains the word
"supine" — which is row 2's hidden answer.** On a grouped card all rows hide together, so
row 2 ("In shock → packaged and placed ___") is decodable from row 3's visible key text — a
verbatim answer-echo on the same face (rule 3). The reference is semantically unavoidable
(pregnancy's trigger IS being supine), so no rewording fixes it. The parent explicitly
licensed the split ("or split per condition if your editor-instincts say the rows interfere").

Result: three per-condition notes (S1–S3), each cold-solvable in isolation, plus the licensed
single vignette (S4, the parent's own exemplar: late-pregnancy hypotensive supine → action).
Because the set was chunked, S1–S3 each carry the full three-row set under `Roster:` with that
note's own member bolded (rule 23 / part-and-whole). Word answers → rule 25 does not apply.
